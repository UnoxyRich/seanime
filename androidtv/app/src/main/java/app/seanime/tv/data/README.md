# Native API contract

This package talks directly to the unchanged Go server. It does not execute React, a web bundle, or browser bridge code. `SeanimeApiClient` handles HTTP envelopes, explicit cancellation, server password hashes, signed client identities, Android TV platform headers and reconnecting `/events` WebSockets. The application owns the client's lifetime and must close it when its owner is destroyed. `snapshotSession()` and `restoreSession()` transfer an immutable, redacted session between owners in process memory only; they do not implement persistence or serialization. Restore is limited to the exact canonical origin (scheme, host and port), and replaces ID, signed proof and hashed token atomically before new requests. Epoch/generation guards reject identity writes from old HTTP requests and sockets after handoff.

## Server evidence

- Media identities are `Long` throughout the Android client. `internal/customsource/customsource.go:27–40,165–170` uses normalized custom-source IDs starting at `2^31`, beyond Kotlin `Int`; the supported wire range is positive integers through `2^53−1`. `MediaIdentity.kt` validates that range without truncation. Episode/page/count values and database playlist/rule/profile IDs retain their separate integer contracts. Boundary tests cover `2147483648`, values above `2^32`, and `9007199254740991` through collections, routes, requests, events, native playback/recovery and plugin episode identity; those tests require the current source candidate's build/runtime evidence before acceptance

- Registered routes: `internal/handlers/routes.go`
- Envelope and errors: `response.go`, `routes.go:RespondWithError`
- Password header: `server_auth_middleware.go` (`X-Seanime-Token` is the SHA-256 hex password hash). WebSocket password authentication uses the same hash in the `token` query parameter. The client never forwards these headers to another origin or follows redirects
- Identity: `client_identity.go` and `websocket.go`; signed `X-Seanime-Client-Id` plus `X-Seanime-Client-Id-Proof`; `androidtv` platform. HTTP identity is established before events; subsequent server changes are adopted
- Library shape: `internal/library/anime/collection.go` (`lists[].entries`, `stream.anime`, `stream.listData`). AniList collections use `MediaListCollection.lists[].entries`; search uses `Page.media`
- Media outside the user's list: `internal/library/anime/entry.go:NewEntry` calls `Platform.GetAnime` when the collection has no entry, so `/library/anime-entry/:id` works for discovery results
- Manga assets: `manga.go:HandleGetLocalMangaPage`, `internal/manga/providers/local.go:LocalServePath`; local provider references must be encoded as one path segment. Downloaded containers use `/manga-downloads/`. Native image requests attach provider headers directly for remote pages and server identity only for the server origin
- Torrent/debrid selection: `torrentstream/previews.go` and `debrid/client/previews.go` both return arrays; `torrentFilePreviews` normalizes these into `{files:[...]}`. Both starts specify `playbackType: nativeplayer`; the actual video arrives on `/events`
- Plugin permissions: `extensions.go:HandleGrantPluginPermissions` sends a targeted challenge. `grantPluginPermissions` subscribes before requesting that challenge and responds only for the requested extension. UI must first show the permissions and get explicit approval
- Setup: `settings.go:HandleGettingStarted`, model definitions in `internal/database/models/models.go`; defaults derive from `seanime-web/src/lib/server/settings.ts`. The native setup uses the existing built-in `seanime` torrent client and validates returned settings

## Existing server contracts and native-client limits

1. MyAnimeList has registered `/mal/auth` and `/mal/logout` endpoints. A `HandleEditMALListEntryProgress` function is documented in `mal.go`, but `/mal/list-entry/progress` is not registered in `routes.go`. The existing MAL token handler also does not check the upstream OAuth HTTP status before storing its token response; the native repository validates non-empty `access_token` and `token_type` and surfaces failure instead of claiming successful sign-in. The unchanged server may already have saved the failed response, so a fresh sign-in is required. There is no independent registered MAL search/list endpoint. The native interface uses the shared AniList/local lists and existing server MAL tracking integration
2. `/playback-manager/start-playlist`, `/playback-manager/cancel-playlist`, and `/playback-manager/playlist-next` are legacy no-op success handlers in `playback_manager.go`. Playlist CRUD is real (`playlist.go`), while playback must use the actual WebSocket playlist protocol in `events_webview.go` and native playback coordinator. The repository deliberately does not expose misleading success wrappers
3. Nakama has no `/nakama/status` REST endpoint. `nakamaStatus()` combines persisted settings with `/nakama/room/available`; live peers, room URLs, watch-party state, chat and synchronization come from the existing Nakama WebSocket protocol. `/room/disconnect` is host-only and must not be presented as a peer disconnect
4. Plugin presentation is a native-client implementation boundary, not a missing server API. Existing `internal/plugin/ui/events.go` exposes declarative controls, screen navigation, HTML/webview and DOM commands. The native client implements declarative tray/forms/commands, permission challenges, typed screen navigation/reload, native menus for the nine page/library/media/episode action families and custom episode tabs. Native viewport and confirmed clipboard adapters use their existing event contracts. CSS queries return truthful empty/null responses because Compose contains no browser DOM; no fake DOM object or mutation success is emitted. Arbitrary HTML/DOM scripts and custom CSS presentation are not interpreted. Exact feasibility and remaining promise/protocol limits are recorded in `androidtv/acceptance/2026-09-30-native-plugin-contract.md`. Episode-tab collections must identify their title as described below
5. Report export is a binary ZIP from `/report/issue/download`, not a JSON envelope. Native reports contain server diagnostics and a user description, not fabricated React/browser recordings
6. Transport unit tests exercise fixture envelopes and HTTP requests. Provider availability, real account OAuth, media codecs, remote Nakama peers and actual image/video streams require device/integration acceptance; passing these unit tests is not evidence of those workflows
7. AniList connection changes require online mode. `internal/core/anilist.go:LoginToAnilist` and `LogoutFromAnilist` replace the active platform without clearing the persisted offline flag, while `internal/core/app.go` prioritizes that flag during startup. The Android client reads current status before sign-in, its callback and sign-out; an offline account must explicitly return online first. MAL connection removal does not replace that platform. The existing status response has no MAL connection field, so the native account menu does not invent a connected/disconnected indicator
8. Local-account migration has a real `POST /local/sync-simulated-to-anilist` route (`internal/handlers/local.go:221`). It is different from uploading tracked offline progress through `/local/anilist`. `internal/local/manager.go:SynchronizeSimulatedCollectionToAnilist` ignores each anime/manga `UpdateEntry` error, refreshes collections and returns success; the endpoint cannot report which entries succeeded. Native TV names the connected account, confirms possible list updates, rechecks the account/mode before sending, and reports request completion with a prompt to review AniList. It does not claim every title was uploaded
9. Manga queue rows are not a worker-completion contract. `internal/manga/downloader/queue.go:Stop` cancels current work and changes its row state without joining the worker; `internal/database/db/chapter_downloader_queue.go:ClearAllChapterDownloadQueueItems` removes database rows only. Waiting or paused rows may still belong to canceling work. Native TV follows queue events, labels Pause as a cancellation request and allows Clear only after a fresh read confirms every remaining row is terminal `errored`. The API provides no quiescence token or conditional clear operation for pending/canceling work
10. Offline metadata `POST /local/local` starts asynchronous synchronization (`internal/local/manager.go:620`). `/local/queue` and `sync-local-queue-state` show current processing tasks, not the buffered job count. `sync-local-finished` is a server-wide processing signal without a request ID or per-title results; `internal/local/sync.go` can emit it after logging synchronization errors. The native client distinguishes request acceptance, observed processing and the finish signal, and never treats an empty queue snapshot as successful completion
11. Built-in torrent `set-limits` changes the current in-memory limiters (`internal/torrent_clients/builtin_client/builtin.go:785`); no endpoint reads the active values back, and settings retain startup defaults. Native controls label these session limits and report request acceptance, not persistence. Torrent recheck is launched asynchronously by `internal/handlers/torrent_client.go`; its HTTP acknowledgement is not a completed hash-verification result. Observable file priorities, trackers and mode changes are read back separately
12. Auto-downloader rule creation has no client idempotency token or conditional revision (`internal/handlers/auto_downloader.go:HandleCreateAutoDownloaderRule`). Native batch creation reconciles known desired rows and retains uncertain responses without blindly reposting, but cannot eliminate another client's write between a fresh read and POST. Finished-rule cleanup reviews and deletes explicit IDs; it does not call the `-1` shortcut, which ignores individual delete errors

Playlist replacement updates have no revision or conditional-write contract (`internal/handlers/playlist.go:HandleUpdatePlaylist`). Native edits re-read current server state immediately before applying the specific operation, preserve other episodes/completion, and refresh on playback events and foreground return. A concurrent writer between that final read and replacement PATCH can still race; eliminating that last window would require a server API change, which is outside this Android-only work.

List date editors use the matching raw AniList collection entry, whose nullable year/month/day components remain intact. Detail dates are normalized strings and cannot recover unknown components. Existing Go simulated/offline implementations support nullable component replacement; the live GraphQL client omits null components, so native live-date edits require a complete calendar date and preserve an unedited partial date. Online clearing is unverified and is not offered as a supported operation. File-match edits similarly merge only the edited fields into a fresh indexed-file snapshot before calling the existing replacement PATCH; the API has no revision check for the final read/write interval.

## Confirmed discovery query gap

`internal/api/anilist/list.go:189–194` accepts `countryOfOrigin`, but the registered `ListAnimeDocument` in `internal/api/anilist/client_gen.go:9016–9025` neither declares nor uses it. The native filter does not promise an ineffective country selector. That same query explicitly excludes MUSIC format. Tag suggestions come from `/api/v1/anilist/collection/raw/tags`, which returns collection-derived tags and no suggestions for a simulated local profile; native custom tag entry remains available.

Manga discovery has a distinct supported query: `ListMangaDocument` accepts country/year but explicitly excludes NOVEL. `internal/api/anilist/list.go:258` multiplies its integer `averageScore_greater` by ten, so native manga score thresholds use 0–9 while anime uses 0–99. These are not interchangeable payloads. Recent-airing discovery uses the custom query at `list.go:484`, with time bounds and sort; its accepted `Search` argument is not declared in that query. The native schedule therefore exposes actual date ranges and upcoming/all-in-range selection rather than a title field that the server would ignore. It follows the existing caller's Japanese, non-adult, non-TV-short display scope. `/schedule` remains the separate personal collection schedule.

## Plugin episode response identity

`ServerAnimeEntryEpisodeTabEpisodeCollectionEventPayload` in `internal/plugin/ui/events.go:410–412` contains only `episodeCollection`; it does not echo the requested media ID or a request ID. `EpisodeCollection` in `internal/library/anime/episode_collection.go:32–36` contains `episodes` and `metadata`. The existing identity fields are `metadata.mappings.anilistId` (`internal/api/metadata/types.go:20–35`) and each episode's optional `baseAnime.id` (`internal/library/anime/episode.go:29`). The normal creator fills these through the requested anime, but hooks and a plugin's `onEpisodeCollection` callback can replace the collection; `internal/plugin/ui/episode_tab.go:316–336` deserializes the callback result without requiring either identity field.

Native TV accepts a matching positive `metadata.mappings.anilistId`, or a nonempty collection where every episode has a matching positive `baseAnime.id`. Every explicit positive identity must agree with the current title, including when collection metadata is present. For title 21, these are minimal accepted collection bodies:

```json
{"episodes": [], "metadata": {"mappings": {"anilistId": 21}}}
```

```json
{"episodes": [{"episodeNumber": 1, "baseAnime": {"id": 21}}]}
```

A plugin returning only `{"episodes": []}` or episodes without identity is incompatible with safe native response binding. Such a reply may be a delayed response for another title, even when it comes from the selected extension. Native TV clears displayed episodes and shows a title-identity error with refresh/source choices; it never assigns the current title ID to an ambiguous response. Plugins can preserve the existing collection metadata or the existing per-episode `baseAnime` objects to remain compatible without changing the Go API. A later correctly scoped reply recovers normally. Tests cover a real WebSocket title switch, late unscoped and wrong-title responses, invalidation of previously displayed episodes, and a subsequent valid selection.
